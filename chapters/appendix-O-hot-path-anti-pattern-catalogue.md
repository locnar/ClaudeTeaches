# Appendix O — Hot-Path Anti-Pattern Catalogue

> **Consolidates:** every chapter's *Pitfalls & anti-patterns* section (§N.5 or §N.6 of Ch. 1–120), read and re-sorted by **where the sin lives** rather than by chapter, with the one column no chapter provides in aggregate: **the counter, probe or signature that exposes it**. The probe invocations are Appendix I's; the fixes point at the section that develops them. Companion to Appendix C (tuning knobs), D (flags), E (latency numbers), I (commands) and M (the readiness gate); the pre-merge review checklist Ch. 120 §120.4.1 asks for.

**How to use this:** two ways. *As a reviewer*, read the left column of the sections that touch the change (a new queue → O.5; a new container → O.1 and O.8; a new thread → O.4 and O.6) and ask whether each row applies. *On call*, start from the **symptom** you have — a p99.9 spike every ~N minutes, a flat median with a long tail, throughput that fell when you added a core — find it in the second column, run the probe in the third, and follow the pointer. Each row is one line: **anti-pattern → how it shows up → what exposes it → the fix → where the book develops it**. The "exposes it" column names the cheapest *discriminating* evidence: a counter that moves for this pattern and not for its neighbours. Rows added by the design-pattern chapters (Ch. 49, 50, 55, 104, 105, 111) are marked ◆.

## O.1 Allocation, page faults and memory lifetime

| Anti-pattern | Symptom | What exposes it | Fix | Where |
|---|---|---|---|---|
| Hidden allocation on the "allocation-free" hot path (`std::string` temp, `std::function` capture, `vector` growth, `shared_ptr` copy) | p99.9 spikes with no pattern; occasional µs stalls | `perf probe -x libc malloc` / `bpftrace -e 'uprobe:libc:malloc /pid==$1/ { @[ustack]=count() }'` on the hot thread: must be zero after warm-up; `perf stat -e page-faults` non-zero in steady state | Pools/arenas sized at start-up; `reserve`; SBO under the threshold; allocation-counting test in CI | Ch. 30 §30.5, 31 §31.5, 32 §32.5 |
| Un-warmed memory faulting on first touch (fresh `mmap`, THP collapse, lazy stack) | the *first* message after start/idle is 10–100× slower; `minor-faults` ticks during the session | `perf stat -e minor-faults,major-faults -p <pid>`; `/proc/<pid>/stat` fields 10/12 moving; `perf trace -e 'exceptions:page_fault_user'` | Pre-fault and `mlock`/`mlockall`, `MAP_POPULATE`, touch the slab at start-up, THP `madvise` not `always`, warm the stack | Ch. 30 §30.5, 34 §34.5, 17 §17.5, 62 §62.5 |

| Use-after-free across an arena reset or pool reuse (silent: the slot is reused, not unmapped) | wrong values, not crashes; a fill booked against the wrong order | ASan on a replay (never in production); debug clear-on-free poison (`0xDD`) appearing in a field; stale-handle counter non-zero | Generational handles / slot maps; poison-on-free in debug; outstanding-view accounting | Ch. 31 §31.5, 32 §32.4.4 ◆, 47 §47.5, 49 §49.4.5 ◆, 101 §101.4.2 |

## O.2 Dispatch, type erasure and abstraction cost

| Anti-pattern | Symptom | What exposes it | Fix | Where |
|---|---|---|---|---|
| `std::function` / megamorphic `virtual` in the inner loop | indirect-branch mispredicts; a `call [rax]` per message | `perf stat -e branch-misses,br_misp_retired.indirect`; `perf annotate` showing `call *%rax`; `objdump` of the hot loop | Templates/CRTP, `variant`+`visit` for closed sets, function pointers for one-level dispatch, `final` + devirtualization verified | Ch. 16 §16.6, 22 §22.6, 32 §32.5 |
| "Zero-cost" abstraction that leaked (a missed inline, a copy, a hidden `call`) | the abstracted version is slower than hand-written; extra moves in the asm | `diff` the asm of abstracted vs hand-written (Godbolt / `objdump -d`); `perf annotate` | Verify the diff is empty; `[[gnu::always_inline]]` where justified; fix the copy | Ch. 22 §22.5, §22.6, 4 §4.5 |
| Throwing on a frequent condition; `dynamic_cast` on the hot path | µs-scale spikes on "error" messages; `__cxa_throw` in the profile | `perf record` + `__cxa_throw`/`_Unwind_RaiseException` in the report; `bpftrace -e 'uprobe:libstdc++:__cxa_throw { @=count() }'` | `std::expected`/error codes on the hot path; exceptions for truly exceptional, off-path conditions; `noexcept` moves | Ch. 24 §24.6 |
| Non-`noexcept` move constructor → silent copies in containers | unexplained bandwidth/time on `vector` growth or `swap` | `static_assert(std::is_nothrow_move_constructible_v<T>)`; the asm shows `memcpy` of whole objects | `noexcept` on moves; `static_assert` in CI | Ch. 24 §24.6 |
| Type-erased senders/coroutine tasks defeating elision | allocation + indirect call where a monomorphic pipeline was intended | `malloc` uprobe; `perf annotate` for indirect calls in the pipeline | Keep the pipeline's types concrete; erase only at the boundary | Ch. 51 §51.6, 52 §52.6 |
| Policy/CRTP used where runtime selection was needed, or runtime selection per call where policies would do | a `switch` per message that is always the same case; or combinatorial template bloat | `perf stat -e L1-icache-load-misses`, `size`/`bloaty` growth; the switch in `perf annotate` | Select the instantiation once at start-up; keep the hot path monomorphic | Ch. 22 §22.6, 16 §16.6 |
| Strong types/units missing: price + quantity, ticks where scaled price expected | wrong orders, not slow ones | a unit test cannot catch what the type system should; review for raw `int64` arithmetic on prices | `Price`/`Qty`/`Notional` wrappers with an allowed-operations matrix; `enum class` ids | Ch. 22 §22.4.4 ◆, 35 §35.6 |
| Modern idioms on the per-message path: `std::function` as the callback, `views::filter` in the loop, `std::string` as the symbol key | 4× the template form; a 12–35 % slower loop that no longer vectorizes; 11–14 ns and an allocation per key | the loop's asm at the level the TU ships at; an allocation counter; the lookup timed against an interned id | Template parameter or `function_ref`; filter once into an index array; `Sym8`/dense id on the hot path, strings at the edges | Ch. 25 §25.6, 16 §16.6 |

## O.3 Control flow, data dependencies and memory ordering

| Anti-pattern | Symptom | What exposes it | Fix | Where |
|---|---|---|---|---|
| `seq_cst` everywhere (over-strong default) | `mfence`/`lock xchg` per store; store-buffer stalls | `objdump` shows `mfence`/`xchg` on plain publication stores; `perf stat -e cycle_activity.stalls_mem_any` | `release`/`acquire` where publication is the intent; `relaxed` for counters | Ch. 41 §41.6 |
| `relaxed` where publication was needed; wrong seqlock/ring ordering | works on x86, breaks on ARM; torn snapshots under load | TSan (Ch. 53) on the replay; a model checker (CDSChecker/herd) on the protocol; an ARM CI run | Acquire/release pairs; a vetted ring/seqlock; test on weak memory | Ch. 41 §41.6, 45 §45.5, 46 §46.5, 48 §48.5, Appendix A |
| Data race treated as "probably fine"; `volatile` as an ordering tool | heisenbugs; the optimizer "breaks" it at `-O2` | TSan; `-O2` vs `-O0` behaviour difference | `std::atomic` with the right ordering; never `volatile` for sync | Ch. 41 §41.6, 5 §5.5 |
| Serial dependency chain (single accumulator, `div`/`sqrt` in the chain, `cmov` lengthening the critical path) | IPC far below the port limit; "unrolling didn't help" | top-down: Backend-Bound/Core-Bound with low port utilization; `perf stat -e uops_issued.any,cycles` | Multiple accumulators; reciprocal multiply; break the chain; verify the asm | Ch. 13 §13.6, 15 §15.6, 35 §35.6 |
| Branchless code that is slower (cmov on a predictable branch; a lookup table that misses cache) | `cmov` version slower than the branch; L1d misses on a "fast" table | `perf stat -e branch-misses` (near zero → the branch was fine); `mem_load_retired.l1_miss` on the table | Keep predictable branches; tables that fit L1; measure both | Ch. 15 §15.6 |
| Mis-hinting `[[likely]]`/`[[unlikely]]`; optimizing branches when not Bad-Speculation-bound | no change, or code layout got worse | top-down level 1: Bad-Speculation share before and after | Hint only from a profile; PGO | Ch. 15 §15.6, 14 §14.6 |
| Branch chain instead of a bitmask in a validation gate (risk checks) ◆ | each reject mispredicts; the all-pass path pollutes the predictor | `perf stat -e branch-misses` scaled with reject rate | Accumulate `r \|= (cond) * BIT`, one branch on the verdict | Ch. 104 §104.2.3, §104.5 |
| Reading the clock inside the deterministic core; timers as callbacks ◆ | replay digest diverges on the first run | Ch. 103 §103.4.6 digest compare live vs replay; `grep rdtsc\|clock_gettime` in core code | Time as an input (`now` stamped once per iteration); timer fires as events | Ch. 103 §103.5, 55 §55.5, 111 §111.5 |
| Floating-point fold / hash-map iteration order inside a replicated fold ◆ | replicas with different histories disagree | replica digest comparison at equal `seq` | Integer state or fixed reduction order; flat arrays; one binary | Ch. 111 §111.5, 35 §35.6, 39 §39.6 |
| Branchless (`cmov`) binary search on a *predictable* key stream (a price walk) | 33 ns where `std::lower_bound` takes 21: the select turned speculable control flow into a serial load chain | `perf stat -e branch-misses` near zero for both, cycles higher for the branchless one; the dependent-chain latency harness | choose per key stream: SIMD scan ≤ 64 keys, branchless on random keys, plain `lower_bound` on a predictable walk, Eytzinger past L2 | Ch. 32 §32.3 row 4, §32.5 |
| A "branchless" ternary that the compiler turned into a branch | Clang 18: 62 ns vs 40 for the same source under GCC; the asm has a `jae` where a `cmovb` was intended | `objdump -d \| grep -c cmov` on the function; Godbolt | write the select as arithmetic (`base += (cond) * half`) or `__builtin_unpredictable`; asm-check in CI | Ch. 32 §32.4.6, §32.5 |
| Per-byte tag/delimiter loops and a tag `if`-chain in a text parser | ~5 ns per field whatever the number conversion costs; one mispredict per field | `perf stat -e branch-misses` per message ≈ field count | layout-pinned parsing (expect the tag order, scan only values), a dense `switch` (jump table), SIMD delimiter find | Ch. 71 §71.3, §71.4.4 |

|---|---|---|---|---|

| A shared counter / `shared_ptr` refcount bumped from many cores | a "pointer copy" costing 50–100 ns | `perf c2c`; `lock xadd` hot in `perf annotate` | Per-thread counters aggregated off-path; pass by reference; single-writer | Ch. 32 §32.5, 42 §42.5, 100 §100.6 |
| Spinning while the holder is preempted; spin without `pause`; lock convoy | ms stalls under load; CPU at 100 % with no progress | `perf sched latency`; `sched_switch` on the lock holder's core; `perf stat -e cycles` vs instructions | Pinned, isolated holders; `pause`; shared-nothing instead of a lock | Ch. 43 §43.5, 54 §54.5 |

## O.5 Queues, pipelines, flow control and timers

| Anti-pattern | Symptom | What exposes it | Fix | Where |
|---|---|---|---|---|
| A thread per concern; staging onto the critical path "to parallelize" ◆ | hop time ≫ work time; tails compounding across cores | Ch. 99's per-stage stamps: time between stages > time in stages; `hops.cpp`-style RTT | Run-to-completion within a shard; stage only off-path consumers or fault domains | Ch. 49 §49.2.2, §49.5 |
| Per-message hops in a burst (no cached indices, no consumer batching) ◆ | microburst → tens of µs of queueing in a 2-stage pipeline | `perf c2c` on the ring's index lines (one transfer per message); queue-depth telemetry | Batch at the consumer; cache the indices; publish once per iteration | Ch. 49 §49.3, 48 §48.4.2, 45 §45.5, 111 §111.5 |
| Polling sources in arrival order, uncapped ◆ | a kill command or an ack delayed by a whole market-data burst | control-message latency under a replayed burst (Ch. 109) | Fixed priority order with per-source batch caps | Ch. 49 §49.4.2 |
| Unbounded queue / "size the ring bigger" ◆ | no drops, but the strategy acts on 20 ms-old data | message *age* at point of use (Ch. 50 §50.4.3), not drop counters | Conflate state; lossless channels sized for the venue burst with fullness = incident | Ch. 50 §50.3, §50.5, 45 §45.5 |
| Ignoring `push`'s return value (drop-newest by omission) ◆ | the newest state lost, the oldest backlog kept | the `Fail` channel's drop counter; stale ages | Declare the policy per channel in the type; publish drops | Ch. 50 §50.4.1 |
| Conflating facts (fills, acks, trade prints); overwriting increments ◆ | missing position, unknown orders, under-reported volume | position vs drop-copy delta; `static_assert(Conflatable<T>)` failing | Facts on lossless channels; merge semantics for accumulators | Ch. 50 §50.4.2, 105 §105.5 |
| Torn reads from an overwrite ring; dirty bit cleared after the read ◆ | garbage ages (10¹⁵ µs), lost updates | an age histogram with impossible values; a lapped counter without a version check | Version word on the slot; clear-then-read | Ch. 50 §50.5, 46 §46.5 |
| Backpressuring the receive path; blocking a hot producer "briefly" ◆ | gaps manufactured on the wire for every consumer | feed gap counters rising while the NIC shows no drops | The receive path never waits; producers fail/overwrite/conflate | Ch. 50 §50.5, 72 §72.5 |
| Wrong Disruptor wait strategy / no wrap protection / allocating in the entry | burned shared core or added latency; overwritten unread slots | CPU time of a non-dedicated consumer; TSan on a 4-slot ring | Match wait strategy to core ownership; gate on the slowest consumer; POD entries | Ch. 48 §48.5 |
| `sleep_for`/`nanosleep`/`epoll_wait(timeout>0)` on a hot thread; a sleeping thread with default timer slack ◆ | 50 µs median lateness; context switches on the hot core | `/proc/<pid>/task/*/timerslack_ns` = 50000; `perf sched`; `cyclictest`/`rtla timerlat` | Hot threads poll a deadline queue; sleepers set `PR_SET_TIMERSLACK=1`, use `TIMER_ABSTIME`/`timerfd` | Ch. 55 §55.3, §55.5, 54 §54.5 |
| `SCHED_FIFO` + busy-poll on a non-isolated core (RT throttle) ◆ | a 38–50 ms stall once per second | `/proc/sys/kernel/sched_rt_runtime_us` = 950000; `sched_switch` to idle on the RT core every second | Isolated cores with the throttle disabled, or `SCHED_OTHER` spinning | Ch. 55 §55.3, 59 §59.5 |
| Unbounded timing-wheel cascade; `std::priority_queue` of cancellable timers; timer-id reuse ◆ | ms stall every 65 k ticks; tombstone-skipping polls; a cancelled guard disappearing | deadline-queue poll p99.9 and max-fires telemetry; stale-timer-id counter | Bounded cascade per poll; heap with position tracking; slot + generation ids | Ch. 55 §55.5 |

## O.13 The ten that pay for the appendix

If a reviewer has five minutes, these are the rows that have most often been the whole incident:

1. Hidden allocation / first-touch fault on the hot path (O.1) — `malloc` uprobe, `minor-faults`.
2. Head/tail or counters on one cache line (O.4) — `perf c2c` HITM.
3. `TCP_NODELAY` missing, or offloads left on (O.7) — the 40 ms mode; `ethtool -k`.
4. A thread per concern; a queue that only grew (O.5) — stage stamps; message age.
5. Default timer slack / RT throttle on a sleeping or spinning thread (O.5, O.6) — `timerslack_ns`; `sched_rt_runtime_us`.
6. IRQs or a sibling on the isolated core (O.6) — `/proc/interrupts`; `rtla osnoise`.
7. `std::function`/`virtual` in the inner loop (O.2) — `br_misp_retired.indirect`.
8. Reading the clock inside the deterministic core (O.3) — the replay digest.
9. The gate or the kill that walks a map or a table (O.8) — their measured time.
10. Reporting the mean (O.11) — the histogram.
